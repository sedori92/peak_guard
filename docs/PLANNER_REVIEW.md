## 2. 에너지플래너 적용 가능성

1차 답변 B2에 따라 에너지플래너가 이미 하는 전력 모니터링·기간별/호실별 조회는 다시 만들지 않고, 새로 더하는 AI 예측·피크 분석만 적용 대상으로 봅니다.
11.11 답변(기업 API 제공·직접 연결 불가)에 따라 지금은 독립형으로 동작하고, 연계는 아키텍처와 코드로 제출합니다.

| 피크가드 기능 | 에너지플래너에 붙이는 방법 | 필요한 것 | 판단 |
|---|---|---|---|
| 다음 1시간 예측·위험 판정 (화면 ①) | 15분마다 기업 MariaDB에서 새 실측 읽기 → 예측 → 결과를 조회 API 또는 결과 테이블로 전달 | MariaDB 읽기 계정 (`.env` 의 `LIVE_DB`) | 조건부 가능 — 코드 준비됨, 접속 정보만 필요 |
| 점검 우선 Top 5 호실·협조 요청 | 에너지플래너의 기존 입주사 알림 경로로 피크가드 문구·대상 호실 전달 | 기업 내부 알림 기능 (개인정보는 기업 안에서만) | 조건부 가능 — 문구·대상 산출은 준비됨 |
| 피크 이력·실측 영향도 보고서 (화면 ②, .xlsx) | 일·주·월 단위로 만들어 관리자에게 제공 | 없음 | 바로 가능 |
| 사용패턴 분석 (요일·시간대, 이상 패턴, 절감 시간대) | 월 1회 묶음 실행 결과를 보고서에 첨부 | 없음 | 바로 가능 |
| 모델 재학습 | 월 1회 또는 계절이 바뀔 때 `python run.py 3` | 학습용 서버(CPU로 약 10분) | 바로 가능 |
| 기상 자료 | 기상청 API허브 키로 15분마다 자동 업데이트 | API 키 (`WEATHER_API`) | 바로 가능 (예측 입력은 현재 미사용) |

## 3. 한계 (결과를 해석할 때 주의할 점)

1. **자료 기간**: 2026-06-29 ~ 11-02, 약 4개월. 겨울(난방기) 자료가 없어 계절이 바뀌면 성능이 달라질 수 있습니다.
2. **수집 중단**: 10-06 ~ 10-20 통신회선 교체로 자료가 없습니다(11.06 답변). 시험기간 첫날은 전일 자료가 없어 일부만 비교했습니다.
3. **건물 합계의 의미**: 96채널 단순합이며 한전 공식 최대수요전력이 아닙니다(3차 답변). 상·하위 회로 관계는 CSV만으로 확정할 수 없습니다.
4. **평가 표본**: 시험기간 실제 위험 39건, 피크 사건 8건으로 적습니다. 재현율 1건 차이가 약 2.6%p입니다.
5. **헛경보**: 정밀도 52%로, 위험 경보 2번 중 1번은 실제로 기준을 넘지 않았습니다. 피크를 놓치지 않는 쪽을 우선한 결과입니다.
6. **Bi-LSTM 시드 흔들림**: 선정 모델 Bi-LSTM 은 시드(난수 시작값)만 바꿔도 시험기간 위험 감지가 9~36건(39건 중)으로 흔들립니다. 발표 숫자(35건)는 시드 42 결과이며, 나쁜 시드는 학습이 일찍 멈춘 경우로 검증기간 오차에서 미리 드러납니다 ([TUNING.md](TUNING.md)).
7. **수요전력 산식**: CSV에 계산 주기·산식이 없어 15분 평균전력으로 확정하지 않았습니다(추가 답변 1-2).

## 4. 개선 방향

| 구분 | 내용 | 기대 효과 |
|---|---|---|
| 단기 (연계 후 1~2개월) | 기업 DB 연결 후 실제 운영 상태로 15분마다 예측을 기록(`live_forecast`)하고, 매주 실측과 비교 | 시험기간이 아닌 실제 운영 성능 확인 |
| 단기 | 헛경보 줄이기 검토: '2번 연속 위험일 때만 알림', 위험 시간대(평일 13:30~16:45)에만 알림 등 운영 규칙을 운영 기록으로 비교 | 입주사 협조 요청 피로 감소 |
| 중기 | 겨울 자료가 쌓이면 `python -m peakguard.models.train --compare` 로 기상 포함·미포함 재비교, 효과가 있으면 `USE_WEATHER=True` | 계절 변화 대응 |
| 중기 | 계측 회로 대응표(호실·공용 상하위 관계) 확보 → 중복 없는 건물 합계로 다시 계산 | 피크 기준·영향도의 정확성 |
| 장기 | 재실·냉난방 운전 이력 등 보조 자료가 생기면 입력 후보로 추가해 같은 절차(검증기간 비교)로 채택 여부 판단 | 피크 원인 설명력 향상 |
| 단기 | Bi-LSTM 학습 안정화(조기 종료 조건 완화) + 시드 여러 개 예측 평균(앙상블) | 시드에 따른 성적 흔들림 감소 |
| 장기 | 모델 재학습·성능 감시 자동화 (검증 MAE가 기준 이상 나빠지면 재학습 알림) | 운영 중 성능 저하 방지 |
